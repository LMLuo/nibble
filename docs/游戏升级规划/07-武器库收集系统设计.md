# 07 · 武器库收集系统设计

**定位**：战斗后奖励重做的第一步——**纯收集向武器库**。击杀掉武器、建大图鉴、稀有难出、**不影响任何战斗数值**。
**状态**：已落地（掉落 + 保底 + 存档 + `arsenal` 命令 + 完整 UI：状态栏/卡片/战利品 toast/手持武器/武器库图鉴页 + 80 把独立像素素材）。

---

## 一、设计决策

| 决策 | 结论 | 理由 |
|---|---|---|
| 武器有没有实际作用？ | **无**（纯收集） | 不碰战斗平衡，实现量最小，内容可无限扩 |
| 什么时候掉落？ | 每次**击败**敌人必掉 1 把 | "击杀后给一个武器"，与捕获与否无关 |
| 稀有武器怎么出？ | 加权随机 + **40 次保底** | 惊喜感 + 防挫败 |
| 重复武器怎么办？ | 图鉴登记 1 次，持有数 +1（×N 显示） | 硬币经济留作后续扩展，本版不引入 |
| 数据放哪？ | `hooks/weapons.js`（与 `pixels.js` 同模式） | 零依赖、随 `sync-lib` 进扩展；阶段 0 可迁移为 `rules/weapons.json` |

## 二、武器库构成（首发 80 把）

| 稀有度 | 数量 | 掉率 | 命名风格（代码世界风） |
|---|---|---|---|
| 普通 | 40 | 70% | 空指针匕首、注释小刀、回车锤、捕虫网 |
| 稀有 | 25 | 22% | 重构之刃、递归长弓、协程长鞭、堆收割者 |
| 史诗 | 12 | 7% | 死锁战锤、熵减法杖、段错误镰、GC 处刑斧 |
| 传说 | 3 | 1% | 归零圣剑·零号机、熵之终焉·热寂、创世提交·初始哈希 |

- **保底**：连续 40 次未出史诗以上 → 下次必出史诗（清零计数）。
- 传说不进保底，保持"真·稀有"。

## 三、数据与接口

```jsonc
// save.json 新增字段（v1 兼容，旧档自动补默认值）
"arsenal": {
  "owned": { "refactor_blade": 2 },   // id → 持有数
  "pity": 13                          // 保底计数（出史诗/传说清零）
}
```

| 模块 | 内容 |
|---|---|
| `hooks/weapons.js` | `WEAPONS`（80 条 `{id,name,rarity}`）、`WEAPON_INDEX`、`WEAPON_TOTAL`、`RARITY_COUNTS`、`PITY_LIMIT`、`rollWeapon(pity)`（加权随机 + 保底，返回 `{weapon, pity}`） |
| `hooks/nibble.js` | `freshSave/loadSave` 兼容 `arsenal`；`attack()` 击败分支掉落并追加日志 `✦ 获得 稀有·重构之刃！`；`arsenalCard()` 渲染武器库卡片；`reset()` 一并清空武器库 |
| `hooks/cli.js` | `do arsenal` → 输出武器库卡片 |
| `commands/nibble.md` | 用法提示加 `arsenal` |
| `tools/sync-lib.js` | 同步列表加入 `weapons.js`（扩展侧 `lib/nibble.js` 依赖它） |

## 四、武器库卡片（`/nibble:nibble arsenal`）

- 头部：`已收集 X/80`、`保底 n/40`、各稀有度进度。
- 主体：按 传说→史诗→稀有→普通 分组列出已收集武器（重复 ×N），未收集不显示。
- 全新档提示"击败一只野生敌人即可掉落第一把"。

## 五、与规划文档的关系

- `00` G4（数据驱动）：加武器 = 加一条数据，不改核心代码。
- `01` 机制 E（收集图鉴）：武器库是图鉴体系的第一块拼图。
- `03` 内容规划：武器命名风格与代码世界世界观一致。
- `04` 阶段 0~1：本 MVP 属阶段 0 的"数据驱动化 + 战斗结算扩展"，先于阶段 3 的完整图鉴落地。

## 六、后续调味（均不破坏"纯收集"，按需再做）

> 其中"外观装备（手持武器）"与"图鉴"已随 UI 版落地（见第七节）。

1. **外观装备**：小生物手持最近获得的武器（纯像素表现，`pixels.js` 加武器贴图位）。
2. **图鉴里程碑**：收集 25%/50%/100% 给称号/皮肤（一次性奖励）。
3. **重复转硬币**：`owned` 计数之外的重复转化为硬币，接阶段 3 的积分经济。
4. **迁移 `rules/weapons.json`**：阶段 0 做数据层统一时迁走，本文件只留加载器。
5. **武器像素图标**：12×12 图标 + 稀有度边框色（复用 `RARITY_COLOR`）。

## 七、UI 呈现（已落地，P0~P3）

| 层 | 内容 |
|---|---|
| P0 文本 | 状态栏 tooltip 加「⚔ 武器库 X/80 · 保底 n/40 · 最近获得」；命令卡片加武器库行；战斗日志中 `✦ 获得 …` 按稀有度着色 |
| P1 掉落高亮 | `save.lastDrop = {id, at}`（掉落时间戳）→ 扩展 tick 检测变化 → 面板弹**战利品 toast**（武器小图 + 稀有度色边框，2.6s 淡出）；史诗以上面板震动，传说再加金光脉冲 |
| P2 手持展示 | 小生物手边实时显示最近获得的武器像素图（纯展示，`#weapon` canvas） |
| P3 图鉴页 | 面板「⚔ 战斗 / 🎒 武器库」标签页；80 格收集网格：已收集=彩色图标+稀有度边框+×N 角标，未收集=暗剪影+「?」；顶部按稀有度分段的收集进度条；命令 `Nibble: 打开武器库` 直达 |

## 八、素材管线（80 把独立像素图）

- **每把武器都有独立素材**（不是形状复用），稀有度风格递进：普通粗糙简陋（木石）、稀有精良钢铁、史诗紫光魔武、传说金色神器。
- 管线：AI 生成排列图（绿幕底，每张 4×2/3×2/3×1 格）→ `tools/weapons-sprites.mjs` 切片 + 抹水印/边框 + 绿幕清理 + **密度裁剪**（丢弃稀疏光效粒子）→ 24×24 调色板网格 → `plugins/nibble/hooks/weapons-pixels.js`（key=武器 id）。
- 源图：`legacy-mods/assets/weapons/sheets/`；切片：`.../cells/`；人工核验拼图：`legacy-mods/tools/preview/weapons/contact-*.png`。
- ⚠️ `image_gen` 的 `output_dir` 相对**工作区根目录**（不是 `nibble-cb/`），生成后需挪入 `nibble-cb/legacy-mods/`。
- ⚠️ 提示词必须强制「flat chunky pixel art, hard edges, NO glow/particles/anti-aliasing」——带光晕的半写实风格在 24×24 降采样后会碎成噪点（史诗/传说首版因此返工）。

## 九、装备系统与战斗页呈现

**玩家自选展示武器**（`save.equipped`）：

| 状态 | 战斗页展示 | 操作入口 |
|---|---|---|
| 未装备（默认） | 最近获得的那把 | 零配置 |
| 已装备 `equipped=<id>` | 该武器 | 武器库详情卡 →「装备此武器」（只接受已拥有的 id，否则自动回落） |
| 「跟随最近获得」 | 回落为最近获得 | 详情卡按钮，清空 `equipped` |

- 战斗页两个更换入口：**点装备槽** 或 底栏 **「更换武器」按钮** → 切到武器库并选中当前携带的武器。
- 图鉴中已装备的格子显示 `★`；状态栏 tooltip 与命令卡片显示「携带：稀有·xxx」。
- 接口：`equippedWeapon(s)` / `equipWeapon(id)` / `arsenalSummary().equipped|.shown`。

**战斗页呈现：独立装备槽**（`.slot`，位于小生物与 ⚔ 之间）：

1. **不与小生物重叠**：武器单独占一个圆角格子（72px；停靠视图 54px），内放素材等比缩放，杜绝"贴脸/穿模"；
2. **稀有度即视觉**：槽边框与淡外发光按稀有度着色（普通橙 / 稀有金 / 史诗紫 / 传说金）；
3. **自带说明**：槽下方显示武器名（过长省略）；悬停显示「名称（稀有度）· 点击更换武器」；
4. **空槽状态**：未打出武器时显示虚线框 + `?` + 「未装备」，提示点击去武器库选择；
5. **尺寸统一**：素材加载统一走 `weaponSpriteGrid(id, true)`——裁剪到内容包围盒并等比放大填满 24×24，避免 80 张素材留白不一导致的大小参差。

> 早期曾尝试"武器贴在小生物身上/身后"，实测重叠观感差，已改为独立装备槽方案。

## 十、加武器流程（维护）

1. 在 `hooks/weapons.js` 的 `WEAPONS` 数组追加 `{id, name, rarity}`（id 唯一、不得与现有重复）。
2. 无需改任何核心代码；旧存档不受影响（未知 id 会在读档时被丢弃，不报错）。
3. 若改了 `weapons.js`，记得 `npm run sync`（或让打包流程自动同步）再本地验证。

## 十一、武器库页面布局（分组网格 + IDE 窄栏适配）

**布局组成**（自上而下）：

1. **比例进度条**：4 段宽度 = 各稀有度武器总数占比（普通 40 / 稀有 25 / 史诗 12 / 传说 3），段内填充 = 该档收集率。避免"4 条等宽彩条"式的杂乱。
2. **统计行**：`⚔ 24/80` + 各档 `稀有 6/25`（带稀有度色点）+ 右侧 `保底 13/40`。
3. **详情卡（单行）**：图标 + 名称/稀有度 + 故事 + 右侧装备按钮，窄栏自动折行。
4. **分组网格**：按 普通 → 稀有 → 史诗 → 传说 分组，每组一个标题（色点 + `14/40`）+ 自适应列数网格。
   - 已收集：右上角稀有度**色点**（不再用边框区分，减少杂色）+ 右下 `×N` + 左上 `★`（已装备）；
   - 未收集：**仅暗剪影**（去掉 `?` 叠字，大幅降噪）；
   - 图鉴素材用 `weaponSpriteGrid(id, 'box')`（缩到 17 内框），细长剑与胖锤视觉重量一致。

**⚠️ 踩坑：IDE 停靠模式（`body.in-view`）与网页/标签页不一致**

成因：早期存在两条**无差别命中所有 canvas** 的规则
```css
canvas { width:216px; height:216px; }
body.in-view canvas { width:132px; height:132px; }
```
`body.in-view canvas`（0,1,2）的优先级高于 `.wcell canvas`（0,1,1），于是**只有停靠模式**会把图鉴每个格子的图标撑成 132px，格子被挤成 3 列、图标溢出——网页预览（无 `in-view`）看起来却正常。

修法：删掉这两条通配规则，改为只给战斗精灵显式设尺寸：
```css
canvas { display:block; image-rendering:pixelated; }
#player, #enemy { width:216px; height:216px; }
body.in-view #player, body.in-view #enemy { width:132px; height:132px; }
```
**规范**：新增组件（图鉴/详情卡/toast 等）一律用**类选择器**给 canvas 定尺寸，禁止再用 `canvas` / `body.in-view canvas` 这类通配写法。

**验证要求**：UI 改动必须在 **3 种载体 × 多种宽度**下截图确认——
`编辑器标签页（无 in-view, ≥900px）`、`停靠面板（in-view, ~1000px）`、`停靠面板窄栏（in-view, ~520px / ~420px）`；并检查 `scrollWidth > clientWidth`（横向溢出）。
