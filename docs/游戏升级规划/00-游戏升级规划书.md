# Nibble 游戏升级规划书（总纲）

**版本**：v1.0（规划基线）
**基线游戏**：Nibble v0.1.1（CodeBuddy 插件 + VS Code/CodeBuddy 扩展，Roguelite 战斗 + 跨会话存档）
**文档定位**：本规划书为升级方案的"总纲"，覆盖升级目标、整体方向、核心玩法机制、可扩展系统、内容规划、开发阶段、优先级、风险点、文档目录与维护方式。详细设计见 `01`~`06` 分册。

---

## 1. 现状回顾（为何要升级）

**现有能力（v0.1.1）**
- 一只 24×24 真彩像素小生物，常驻状态栏 + 底部面板，逐帧待机动画。
- 核心循环：用户向 CodeBuddy 提问（`UserPromptSubmit` 节拍）→ 小生物攻击一只野生敌人 → 战斗日志 → 击败/捕获 → 刷新更强的下一只。
- Roguelite 数值：攻击力 `4 + 等级×2`，敌人 HP 随等级增长，稀有度随等级提升，经验/升级连续结算。
- 跨会话存档：`save.json`（等级/经验/战绩/当前敌人）。
- 三种触发模式：`hook`（提问即攻击，需配套插件）/ `onSave`（保存即攻击）/ `manual`（仅按钮）。
- 强隐私承诺：hook 只取"节拍"，**绝不解析 prompt / 代码 / 文件路径**，战斗走 `systemMessage` 不进模型上下文、不耗 token。

**主要局限（升级动因）**
1. 玩法单薄：只有"攻击→升级→换更强的怪"一条线，缺乏养成、收集、目标感。
2. 缺少个性化：所有玩家进程一致，小生物不能反映"你是哪类开发者"。
3. 战斗无策略：攻击数值固定，无连击/暴击/技能/属性克制。
4. 内容空泛：没有物种、技能、成就、剧情等可消费的内容。
5. 留不住人：无日常、无赛季、无收集目标，新鲜感过后易流失。
6. UI 利用不足：底部面板仅显示战场，未承载图鉴/任务/互动等丰富交互。

> 升级的核心命题：**在"绝不读取代码内容"的隐私承诺下，把"写代码这件事"本身变成一场好玩、个性化、可持续的游戏。**

## 2. 升级目标（SMART）

| 编号 | 目标 | 衡量标准 | 目标版本 |
|---|---|---|---|
| G1 | 玩法从"单线战斗"升级为"养成 + 战斗 + 收集"复合循环 | 玩家平均会话内有 ≥3 类主动游戏行为（攻击/进化/任务/互动） | v0.3 |
| G2 | 引入"行为画像 → 进化分支"，让小生物反映玩家编码风格 | 上线 ≥3 条可进化分支，且分支由可观测行为（非代码内容）驱动 | v0.4 |
| G3 | 战斗具备基础策略（连击/暴击/属性/技能） | 玩家攻击决策出现可观测差异（非纯随机） | v0.3 |
| G4 | 建立可数据驱动的内容体系（物种/敌人/技能/成就） | 新增一个物种/技能/成就无需改核心代码，仅增配置 | v0.2 |
| G5 | 提供长期目标（日常/成就/赛季），提升 7 日留存 | 7 日留存较现状提升 ≥30% | v1.0 |
| G6 | 全程守住隐私承诺，并提供"权限分级"让用户自选 | 默认零读取；任何需读 IDE 状态的功能均为显式 opt-in | 贯穿全部版本 |

## 3. 整体方向（设计哲学）

遵循四条原则，所有机制设计以此为锚：

1. **行为即玩法（Behavior-as-Gameplay）**
   不读代码内容，但"你做了什么动作"本身就是游戏事件：提问、保存、提交、跑测试、出现报错、长时间专注、短暂离开……把这些**动作节拍**映射成战斗/养成事件。

2. **情绪转化（Turn Pain into Play）**
   把开发中的负面体验转化为正面反馈——报错=出现可击败的怪物、技术债=精英怪、长时间卡 bug=蓄力槽。让"debug 很烦"变成"我在打 boss"。

3. **个性化进化（Your Pet, Your Style）**
   小生物的生长路径由你的行为画像决定（多写测试→守护型；多 debug→猎手型；多写文档→智慧型）。它成为你在代码世界里的"数字分身"。

4. **轻量不打扰（Ambient, Not Intrusive）**
   默认仅状态栏 + 面板常驻显示，战斗日志一行带过；任何强交互（图鉴/任务/装饰）都需用户主动打开面板，绝不强弹窗、绝不消耗 token。

## 4. 核心玩法机制（总览）

> 详细逐条设计见 `01-核心玩法机制.md`。此处给出机制地图与重点结论。

**机制分层（从底到顶，越往下越基础、越往上越"好玩"）**

| 层 | 机制 | 一句话价值 |
|---|---|---|
| L0 事件 | 行为驱动事件体系 | 把"写代码动作"变成游戏事件源（不读内容） |
| L1 战斗 | 连击 / 暴击 / 属性克制 / Boss 战 / 策略 | 让战斗从"无脑砍"变"有策略" |
| L2 养成 | 属性养成 / **行为画像进化** | 让小生物"长成你的样子"（差异化核心） |
| L3 技能 | 可学技能 / 被动光环 / 组合技 | 提供 build 多样性与正反馈 |
| L4 收集 | 物种图鉴 / 怪物图鉴 / 皮肤 | 长期目标与收集快感 |
| L5 目标 | 成就 / 日常 / 赛季 | 留存引擎 |
| L6 互动 | 抚摸 / 喂食 / 小窝装饰 | 情感绑定 |
| L7 场景 | 环境地形 / 世界剧情 | 世界观厚度 |
| L8 社交 | 好友组队 / 排行榜（需后端，谨慎） | 可选的长期扩展 |

**结论——哪些更好玩（重点）**
- 🥇 **行为画像进化**是第一差异化卖点：别人没有"你的宠物长成你的编码风格"这种体验。
- 🥈 **情绪转化**（报错=怪物、卡住=蓄力）把痛点变爽点，是情绪设计的灵魂。
- 🥉 **连击 / 专注槽 / 暴击**是低成本的"心流"增强，立刻让战斗更带感。
- 收集图鉴 + 赛季排行榜提供"长期再来"的理由。

## 5. 可扩展系统（总览）

> 详细架构见 `02-可扩展系统架构.md`。

- **事件/信号层**：统一事件总线，hook 节拍事件 + 扩展侧 IDE 事件（诊断数变化、git 事件、测试运行）分级接入。
- **数据模型**：`save.json` 演进为多模块结构（creature / battle / collection / quests / meta），支持版本迁移。
- **规则数据化**：物种、技能、敌人、成就全部用 JSON/JS 配置描述，核心代码只读规则。
- **渲染层**：状态栏（轻量）→ 底部面板（战场）→ 交互面板（图鉴/任务/装饰，主动打开）→ 编辑器标签页（大图）。
- **触发层**：保留 `hook / onSave / manual`，新增 `extension-events`（需 opt-in 权限）。
- **扩展点**：预留 mod/插件接口，允许社区贡献物种与皮肤（头像、配色）。
- **隐私分级**：L0 零读取（默认）/ L1 只读聚合信号（如"有 N 个诊断"，不含内容，opt-in）/ L2 需用户显式授权的深度能力。

## 6. 内容规划（总览）

> 完整内容表见 `03-内容规划.md`。

- **物种图鉴**：初始 1 种，进化出 3 大分支（守护/猎手/智慧），每支 3 阶，共约 10+ 可收集形态。
- **敌人/怪物**：把代码世界实体化——`Bug`（小怪）、`技术债`（精英）、`TODO`（成群）、`熵增病毒`（赛季 Boss）。
- **技能**：被动（专注时暴击率↑）、主动（连击终结技）、光环（降低报错出现频率的"护盾"隐喻）。
- **成就/日常**：连续提交 N 天、修复 100 个错误、单局 10 连击等。
- **剧情/世界观**：轻量叙事——小生物来自"代码奇点"，与你并肩对抗熵增。
- **皮肤/赛季**：每赛季一个主题皮肤与限定物种。

## 8. 优先级（MoSCoW）

| 优先级 | 机制 | 理由 |
|---|---|---|
| **Must** | 数据驱动化（阶段 0）、连击/暴击、行为画像进化、图鉴/成就 | 缺失则升级不成立或难留存 |
| **Should** | 属性养成、技能系统、日常任务、专注/蓄力槽、皮肤 | 显著提升乐趣与留存 |
| **Could** | 小窝装饰、环境地形、剧情演出、好友组队 | 增强体验，但可后置 |
| **Won't（本版不做）** | 强制社交、读取代码内容做个性化、付费系统 | 违背隐私原则或成本高/风险大 |

## 9. 风险点（总览）

> 完整清单与缓解见 `05-风险与应对.md`。

| 风险 | 严重度 | 一句话对策 |
|---|---|---|
| 隐私承诺被打破 | 高 | 默认零读取；任何读 IDE 状态功能均 opt-in，且不读内容只读数 |
| hook 运行于 Git Bash + Node16，性能受限 | 中 | 事件处理保持轻量；重计算放扩展侧；守 Node16 语法 |
| 底部面板 UI 空间有限 | 中 | 重交互迁至"主动打开的交互面板"，状态栏只做轻量提示 |
| 机制膨胀导致复杂度失控 | 中 | 严格按阶段 0~5 分期；每机制先登记再实现 |
| 留存不足 | 高 | 日常/成就/赛季构成留存引擎（G5） |
| 跨平台/发布（Windows Git Bash、Open VSX 命名空间） | 中 | 沿用既有 CI 与发布流程，不重构 |

## 11. 后续维护与迭代方式（总览）

> 详细规范见 `06-维护与迭代手册.md`。

- **版本规范**：语义化版本（SemVer），规划内阶段对应 minor  bump，内容热更对应 patch。
- **数据迁移**：`save.json` 带 `schemaVersion`，升级时自动迁移，不丢档。
- **内容热更**：物种/技能/成就走配置，无需发版即可扩展（阶段 0 落地）。
- **反馈闭环**：在交互面板内置"反馈/建议"入口，定期复盘。
- **回归测试**：沿用 `npm test` 扩展自检 + 新增机制单元测试，发版前跑全量。
- **路线图评审**：每季度回看 `04` 里程碑，按 `05` 风险与实际数据调整优先级。

## 12. 一句话总结

> 把"写代码"变成一场**你的宠物因你的编码风格而成长**的游戏：动作即事件、报错即怪物、坚持即进化——轻量常驻、隐私至上、数据驱动、分阶段可落地。
