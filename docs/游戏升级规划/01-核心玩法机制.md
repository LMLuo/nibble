# 01 · 核心玩法机制设计

**定位**：玩法创意库 + 决策依据。回答三个问题——
1. 有哪些机制可以加入？
2. 哪些设计会更好玩？
3. 这些机制如何组合成一套完整升级方案？

**前置约束（必须牢记）**
- 默认**绝不读取代码/prompt 内容**（隐私承诺）。能用的只有"你做了什么动作"这类**节拍/聚合信号**。
- 运行环境：hook 跑在 Windows Git Bash + Node16，需轻量；扩展（IDE 侧）有完整 IDE API，可做更重的 UI 与"只读聚合信号"的游戏化。
- UI 空间有限：状态栏只放轻量提示，重交互放"主动打开的交互面板"。

---

## 一、机制设计原则

| 原则 | 含义 |
|---|---|
| 行为即玩法 | 用"动作节拍"造事件，不靠读内容 |
| 低侵入 | 默认不打扰、不弹窗、不耗 token |
| 正反馈优先 | 把开发中的痛（报错/卡顿/技术债）转成爽点 |
| 可数据驱动 | 机制参数化、内容配置化，易扩展 |
| 个性化 | 让进展反映"你是谁类型的开发者" |

---

## 二、可加入的机制清单（A~I）

### A. 行为驱动的事件体系（一切的基础）
把"你在 IDE 里的动作"映射成游戏事件。**这是升级的地基，没有它后面都做不了。**

| 玩家动作（可观测信号） | 游戏事件 | 所需权限 |
|---|---|---|
| 向 CodeBuddy 提问 | 普通攻击 | L0（已有） |
| 保存文件 | 攻击 / 蓄力 +1 | L0（已有 onSave） |
| 会话开始/结束 | 出战/收工 | L0（已有） |
| 运行测试且通过 | 暴击 / 终结技 | L1（只读"测试通过"布尔） |
| 出现诊断错误/警告（计数变化） | 刷出对应怪物 | L1（只读计数，不读内容） |
| 修复错误（计数下降） | 击败怪物、掉落 | L1 |
| git commit | 大招 / 阶段推进 | L1（只读 commit 发生） |
| git push | Boss 战 / 团队事件 | L1 |
| 连续专注 N 分钟（无 idle） | 进入"专注态"，暴击率↑ | L0（计时即可） |
| 离开/ idle 超时 | 小生物进入睡觉/饥饿 | L0 |
| 新建/删除文件 | 探索新地图 / 环境变化 | L1 |

> 关键设计：L1 权限只取**聚合布尔/计数**（"有 3 个错误""测试通过了"），**不取错误内容、不取文件名语义**。用户可在设置里一键开/关。

### B. 战斗系统升级（让"砍怪"有策略）
| 机制 | 玩法 | 好玩点 |
|---|---|---|
| 连击 Combo | 短时间内连续动作累积连击数，伤害递增 | 心流、爽快 |
| 暴击 | 测试通过 / 专注态触发暴击 | 正反馈 |
| 属性/元素克制 | 设 火/水/草/光/暗 等属性，物种与怪物互克 | 策略深度（轻量版：2~3 属性足够） |
| 技能释放 | 攒满能量放主动技（见 D） | 决策感 |
| Boss 战 | 阶段 Boss（如"熵增病毒"），多阶段血条 | 高潮体验 |
| 策略选项 | 战斗中出现"进攻/防御/治疗"三选一（一键或默认自动） | 轻度 RPG 感 |
| 捕获/收服 | 低血量怪物可收服进图鉴（替代纯击杀） | 收集动机 |

### C. 养成与进化（差异化核心 ★）
**这是全方案里最该做、最能拉开差距的机制。**

- **属性养成**：HP / 攻击 / 防御 / 速度 / 幸运，随等级与养成行为增长。
- **行为画像进化（重点）**：不读代码，只按"动作分布"判定进化方向——
  - 多写测试 + 提交规范 → **守护型**（高 HP/防御，光属性）
  - 多 debug（错误出现又消失频繁）→ **猎手型**（高攻击/暴击，暗属性）
  - 多文档/注释/长会话专注 → **智慧型**（高速度/幸运，水属性）
  - 均衡 → **均衡型**
- **进化树**：每条分支 3 阶（幼体→成体→完全体），形态与配色变化（复用现有像素生成管线）。
- **好玩点**：玩家会主动"为了养出某种形态"而调整习惯，形成**正向行为引导**——这才是最佳游戏化。

### D. 技能系统
| 类型 | 示例 | 来源 |
|---|---|---|
| 被动 | 专注态暴击 +20% | 进化自带 |
| 主动 | 连击终结技"代码风暴" | 攒能量释放 |
| 光环 | "护盾"：降低错误刷新频率（隐喻） | 成就解锁 |
| 组合技 | 特定属性 + 特定技能触发额外效果 | 进阶玩法 |

### E. 收集与图鉴
- **物种图鉴**：已进化/已见过的形态登记（见 `03`）。
- **怪物图鉴**：击败/收服的敌人图鉴，含出场频率统计（"你这周打了 12 只 Bug"）。
- **皮肤图鉴**：可解锁配色/主题。
- 好玩点：收集进度条本身就是留存钩子。

### F. 任务 / 成就 / 日常
- **成就**：连续提交 7 天、单局 10 连击、收服 5 种怪、达到 20 级……
- **日常任务**：今日提交 3 次 / 修复 5 个错误 → 奖励积分。
- **周/赛季目标**：赛季限定挑战。
- 好玩点：给"随便玩"一个明确目标。

### G. 互动与装饰（情感绑定）
- **抚摸**：点一下面板里的小生物，触发开心动画 + 好感度。
- **喂食**：用"积分"（战斗/任务获得）换食物，影响成长速度或外观。
- **小窝**：用积分装饰一个小空间（背景、家具），纯表现。
- 好玩点：从"工具"变成"伙伴"。

### H. 环境 / 场景 / 世界观
- **环境地形**：不同项目语言/类型映射不同场景（前端=霓虹城、后端=机械殿……仅用项目类型等聚合信号，不读内容）。
- **轻量剧情**：小生物来自"代码奇点"，与你对抗熵增；用几条解锁式短文案推进，不做重叙事。

### I. 社交（谨慎，需后端）
- **排行榜**：赛季积分榜（可选匿名）。
- **好友组队**：两只小生物合击 Boss（需联网/后端，成本高）。
- **建议**：v1.0 前不做或仅做本地/匿名轻量榜；明确标注需联网与隐私影响。

## 三、哪些设计会更好玩？（灵魂三问的答案）

**Q1：有哪些机制可以加入？**
A：见上文 A~I。优先级排序（好玩度 × 可行性）：
1. 行为驱动事件体系（地基，必须）
2. 连击 / 暴击 / 专注槽（低成本高爽感）
3. 行为画像进化（高差异、强留存）
4. 图鉴 / 成就 / 日常（留存引擎）
5. 技能 / 皮肤 / 小窝（增强体验）
6. 社交 / 赛季（可选扩展）

**Q2：哪些设计会更好玩？**
- 🥇 **行为画像进化**：别人没有"宠物长成你的编码风格"的体验，且顺带引导好习惯。
- 🥈 **情绪转化**：报错=怪物、卡住=蓄力——把痛点变爽点，是情绪设计灵魂。
- 🥉 **连击 + 专注槽 + 暴击**：立刻让战斗有"手感"和心流。
- 收集图鉴 + 赛季：提供"明天还回来"的理由。

**Q3：这些机制如何组合成完整方案？**
见下一节"核心循环 + 四层架构"。

## 四、机制如何组合成完整升级方案

### 4.1 核心循环（玩家每次打开 IDE 都在转）
```
你写代码 / 提问 / 提交 / 跑测试（动作节拍）
        ↓ 事件体系（A）
刷出/击败怪物、攒连击与能量（B）
        ↓
战斗结算 → 经验/积分/掉落（B/D）
        ↓
养成成长 + 行为画像累积（C）
        ↓ 触发条件
进化分支 / 解锁技能 / 收服图鉴（C/D/E）
        ↓
完成日常/成就 → 解锁装饰/皮肤（F/G）
        ↓
长期：赛季排名 / 图鉴毕业（E/F/I）
```

### 4.2 四层架构（机制 × 系统 × 内容 × 表现）
| 层 | 组成 | 对应文档 |
|---|---|---|
| **核心循环层** | 事件(A) → 战斗(B) → 奖励 → 养成(C) | 本册 + `02` |
| **系统层** | 进化树(C)、技能(D)、收集(E)、任务(F)、互动(G)、场景(H) | `02` 架构 |
| **内容层** | 物种/敌人/技能/成就/剧情/皮肤/赛季的具体数值与文案 | `03` |
| **表现层** | 状态栏提示、战场面板、交互面板、大图、动画、音效（可选） | `02` 渲染层 |

> 一句话：**机制（本册）定义"能玩什么"，系统（02）定义"怎么跑"，内容（03）定义"有什么"，表现层定义"看起来多好"。** 四层解耦，内容可热更、机制可插拔。

### 4.3 机制优先级矩阵（好玩度 × 可行性）
| 机制 | 好玩度 | 可行性 | 建议阶段 |
|---|---|---|---|
| 行为事件体系 | ★★★★★ | ★★★★★（已有基础） | 阶段 0 |
| 连击/暴击/专注 | ★★★★ | ★★★★★ | 阶段 1 |
| 行为画像进化 | ★★★★★ | ★★★★ | 阶段 2 |
| 图鉴/成就/日常 | ★★★★ | ★★★★ | 阶段 3 |
| 技能系统 | ★★★ | ★★★ | 阶段 3 |
| 皮肤/小窝 | ★★★ | ★★★★ | 阶段 4 |
| 场景/剧情 | ★★ | ★★★ | 阶段 4 |
| 社交/赛季 | ★★★★ | ★★（需后端） | 阶段 5（可选） |

## 五、机制登记与变更规范

- 新增机制：先在本册 A~I 追加条目，注明**所需权限等级（L0/L1/L2）**与**好玩度/可行性**。
- 机制进入开发前，必须在 `02` 定义事件与数据模型，在 `03` 补内容，在 `04` 排期。
- 任何需要读取 IDE 状态（哪怕只是计数）的机制，必须标红"需 opt-in 且只读数不读内容"，并在 `05` 登记隐私风险。
