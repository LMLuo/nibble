# 11 · 玩家血量与怪物反击设计

**定位**：给"提问即攻击"的单向节拍补一层**风险**——玩家有血量、每次攻击后怪物**反击**、血量见底即**被击退**；但**零实质惩罚**，血量只是"这一场能不能打完"的节奏资源。
**状态**：**已落地**（第三刀：玩家 HP / 怪物反击 / 被击退 / 8 种怪物属性；前两刀见 `10-技能书与技能库设计.md`）。
**依赖**：`10`（技能标签决定"回复/护盾/反震"的实际价值）、`08-怪物库与难度升级设计.md`（本文要改写它的难度档口径）、`09`（被击退断连击）。

---

## 前置口径改动声明（必须先看这条）

本文**推翻** `08` 既有的难度档决策：

> `08:13` 原文：`| 难度提升走哪一档？ | **A 档：仅数值分级** | 不引入玩家 HP 与失败判定，不改变"提问即攻击"的单向节拍；靠 tier / 稀有度 / 等级三重缩放 + 精英机制变难 |`

`08` 拒绝的其实是**失败惩罚**（输了会亏 → 违背三条筛子），而本文引入的是**风险 + 零惩罚**：

- 血量见底**不降级、不丢武器/技能书/收集进度、不清经验**；
- 只做两件事：**换一只新怪** + **连击归零**（复用既有静默归零机制）；
- 玩家不需要为血量做任何维护（**击杀即回满**，没有药水、没有补给、没有计时恢复）。

因此新口径为 **A+ 档：数值分级 + 风险层（零惩罚）**，需按第十一节逐条改回 `08`。

## 一、设计决策

| 决策 | 结论 | 理由 |
|---|---|---|
| 为什么要血量？ | **把"这场能不能打完"变成可感知的节奏** | 长回合怪（自愈/护盾/分裂）从"慢一点"变成"有代价"，技能书的续航类标签才有戏 |
| 血量从哪来、怎么回？ | `maxHp = round(30 + lv*6)`；**击杀回满** | 零维护：不存在"必须回血"这件事（筛子 1） |
| 怪物什么时候反击？ | **每次玩家攻击后、且敌人生存时** | 就是"提问即攻击"的下一拍，不加新节拍、不动 hooks |
| 反击伤害怎么算？ | **按玩家 maxHp 的百分比**：小怪 5% / 精英 3.5% / 头目 3%，再乘 `RARITY_MUL` | 等级无关、量级稳定，每场都是"约 20~33 下预算"，不会随等级漂移 |
| 见底了怎么办？ | **被击退**：换新怪 + 连击归零 + 满血；**零实质惩罚** | 不产生"卡关"与"亏损感"（筛子 2） |
| 要不要加新系统？ | **不加**：无药水、无防御属性、无装备耐久、无倒计时 | 只复用既有机制（换怪、断连、闪白/消散演出） |
| 怪物属性要扩吗？ | **扩到 8 种**（现有 5 + 尖刺/狂暴/护盾再生），**新 3 种只给精英与头目** | 小怪保持新手期干净；新机制只加"效率压力"，不加"通过门槛" |
| 与技能什么关系？ | 标签与怪物属性**自动对位** | 只影响效率，绝不出现"必须看怪换技能才过得去"（守筛子 2） |
| 战斗页要加血条吗？ | **不加**：玩家 HP 只在状态栏心形条与面板数值上体现 | 场景内已有经验条 + 敌方血条 + 4 个技能槽，再加会糊成仪表盘 |

## 二、为什么现在引入风险层（筛选过程）

| 筛子 | 本设计的处理 | 判定 |
|---|---|---|
| **无负担**（不新增必须做的事） | 杀伤回血是自动的；血量**只能被怪物打掉**，玩家不维护、不补给、不等待 | ✅ |
| **无操作负担**（不新增会亏的决策） | 被击退**不丢任何东西**，也不需要玩家点任何按钮；血量归零由系统处理 | ✅ |
| **不复杂**（不加系统层） | 没有货币/道具/防御属性/倒计时；两大机制（反击、击退）都挂在既有的"提问即攻击"节拍上 | ✅ |
| 会不会变成失败惩罚？ | 明确否定：不降级、不清经验、不掉收集。唯一代价是"这只怪白打了"和连击归零 | ✅ |

**为什么现在做**：前两刀（技能书、随机出手）之后，"长回合怪"会明显变多（玩家把敌人打得更慢/更快由配置决定），此时血量既能给战斗一个自然的收束点，又能让**回复/护盾/反震**三个标签拥有真实价值。

## 四、怪物反击

### 4.1 公式

```js
counter = max(1, Math.round(playerMaxHp(lv) * R[tier] * RARITY_MUL[rarity]))
// R = { common: 0.05, elite: 0.035, boss: 0.03 }
// RARITY_MUL 复用 enemies.js 既有表：1.0 / 1.15 / 1.35 / 1.6
```

**为什么是"按玩家 maxHp 的百分比"而不是固定数值**：敌人 HP 与玩家攻击力都随等级缩放，若反击用 `f(等级)` 的绝对值，致死节奏会随等级漂移；百分比制让每一场都是同一个量级的"血量预算"，也天然支持每只怪的稀有度微调。

### 4.2 致死节奏与安全边际

| tier | 反击占比 | 致死下数 | 击杀需求（无技能） | 安全边际 |
|---|---|---|---|---|
| 小怪 | 5% | **≈20 下**（传说怪 ≈12.5） | 5 击 | **4.0×** |
| 精英 | 3.5% | **≈28 下**（传说怪 ≈18） | 10 击 | **2.8×** |
| 头目 | 3% | **≈33 下**（传说怪 ≈21） | 18 击 | **1.8×** |

> ⚠️ **口径修正**：评审时的临时口径是 `counter = round((2 + lv*0.8) × TIER_MUL)`（小怪≈10 下 / 精英≈5~6 下 / 头目≈3~4 下致死）。按击杀需求复算会发现它**自相矛盾**——头目要 18 击才死，玩家却在 3~4 下就被打退，等于**头目永远打不过**。改用百分比制后，边际 ≥1.8×，原则上所有怪都打得过；**风险只体现在"长回合怪"上**（自愈/护盾/分裂把击杀拖到 25~30 击时，1.8× 的边际会被吃光）。

### 4.3 结算顺序（写死，不允许实现时自由发挥）

1. 玩家攻击：`atk` × 技能倍率 × 标签效果（暴击/贯穿/破甲/精准/追击…）
2. **击杀判定**：敌人 HP 归零 → 走击败分支（掉落、刷怪）→ **不反击**（避免"完成击杀的那一击反而被打退"）
3. 敌人生存 → **尖刺**（固定反弹，不吃护盾类减免）→ **反击**（护盾/铁壁先减伤，再扣玩家 HP）→ **反震/血偿**（按比例反弹 / 回血）
4. 玩家 HP ≤ 0 → **被击退流程**（第五节）
5. 回写日志与 `lastLog`

**例外与边界（实现时按这四条写死）**：
- `追击` 的**追加一击不触发反击、也不额外触发尖刺**（否则追击等于自伤）。
- **分裂**（HP 归零但未击败）**仍会反击**——否则分裂怪永远不打人；分裂后按新个体继续。
- 反震把敌人打死的，**算正常击杀**（走击败分支，经验与掉落照给）。
- 尖刺/反击对玩家的伤害**不吃玩家侧护盾以外的减免**（护盾标签与铁壁只作用于"反击"这一项）。

## 五、失败语义（被击退）

| 项目 | 口径 |
|---|---|
| 触发 | 玩家 HP ≤ 0（只可能在反击后发生） |
| 结果 ① | 玩家**满血**（下次战斗从满血开始） |
| 结果 ② | 当前敌人**丢弃并换一只新怪**（旧怪剩余 HP 不保留——避免"卡在同一只头目上反复被击退"的卡关感） |
| 结果 ③ | **连击归零**（复用既有 `streak.count = 0`，静默无提示） |
| 结果 ④ | 该场战斗**无经验、无掉落**（被击退的那次攻击不给击败奖励） |
| 结果 ⑤ | **绝不**降级、丢武器/技能书/收集进度、清经验 |
| 演出 | 场景闪白（复用 `burst` 的 flash）+ 敌人消散帧 + 日志一句 |
| 日志 | `Nibble 被〈怪名〉击退！血量见底，换一只新怪继续。` |

## 六、怪物属性扩展（8 种）

### 6.1 新增三种机制

| 机制 | 键 | 结算效果 |
|---|---|---|
| 尖刺 | `thorns: N` | 每次受击**反弹 N 点**给玩家（在反击结算前生效） |
| 狂暴 | `enrage: true` | 自身 HP < 30% 时，**反击 ×1.5**（触发一次后持久） |
| 护盾再生 | `reShield: N` | 护盾被击穿后，**每 N 回合恢复 1 层**（上限 = 开场层数） |

**分配口径（已写入 `08` 的怪目表）**
- 新增 3 种属性**只给精英与头目**；小怪保持现有 5 种之内。
- 强度预算：每个精英/头目**最多 1 个"新增机制"**，且机制键总数 ≤3（`debt_singularity` 已满配 4 键 → 不再加）。
- ⚠️ **护盾再生只给"本来就有护盾"的怪**（`mech.shield > 0`）：给无盾的怪等于凭空每 N 回合造一层盾——实测把段错误泰坦从 26.6 击拖到 42.7 击。落地后据此把 `segfault_titan` 改为尖刺、`cascade_avalanche` 改为狂暴。
- 分配结果（14 精英 + 6 头目）：**尖刺 8 / 狂暴 6 / 护盾再生 5**，`debt_singularity` 不加——明细见 `08` 第三节各表的加粗项。
- 强度：尖刺 `2`（头目 `legacy_colossus` 为 `3`）、护盾再生 `2`（`silent_failure` 为 `3`）、狂暴为开关型。

### 6.2 对位表（技能标签 ↔ 怪物属性）

| 怪物属性 | 解题标签 | 说明 |
|---|---|---|
| 护甲 | 贯穿 / 破甲 | 减伤被绕过或被永久削层 |
| 护盾 | 贯穿 / 破甲 | 同上 |
| 护盾再生 | 贯穿 / 破甲 | 必须是"压过再生速度"，靠速杀 |
| 闪避 | 精准 | 命中判定直接绕过 |
| 自愈 | 必暴 / 追击 | 靠单回合爆发压过回血 |
| 分裂 | 必暴 / 追击 | 首击越重越省回合 |
| 尖刺 | 护盾 / 反震 | 减伤 + 反弹 |
| 狂暴 | 护盾 / 反震 | 同上 |

**硬约束**：对位**只影响效率，不影响"能不能过"**。不存在"必须换技能才能打过"的组合——安全边际 ≥1.8× 就是为此存在的（守筛子 2 的"选错会亏"）。

## 七、平衡重校

- **敌人 HP 不上调**：与 `10` 同口径（技能倍率、武器战力、连击都是"玩家侧成长"，敌人不为它们补偿）。本文引入的风险层也**不改敌人 HP**，只新增一项指标。
- `tools/balance-sim.js` 新增输出：
  - **表 B**：击杀所需回合数（**纯伤害对拼**：每击补满玩家血量，保证"打这只怪要几回合"与历史基线可比）
  - **表 C**：**击退率** = 自然血量下"这一场会不会在打死它之前被击退"（每样本一次机会，被击退即失败）
  - 玩家可承受回合数 = `maxHp ÷ counter`（打印在表 C 行尾）
  - 每轮重置：`level/exp/equipped/streak/arsenal/skills/skillSlots/playerHp/playerGuard` 全量重置——照 `:63-66` 的污染警示。
- **验收基准（实测，SAMPLE=150）**：改公式必须同步重跑并回写本表

| 配置 | 小怪 | 精英 | 头目 |
|---|---|---|---|
| 无技能 | **0%** | **0%** | Lv20 **100%** ／ Lv30 **13%** |
| 4 本普通 | 0% | 0% | Lv20 17% ／ Lv30 0% |
| 4 本稀有及以上 | 0% | 0% | **0%** |

- ⚠️ 评审时预期"无技能 头目 ≤30%"被实测推翻：**第一只头目（段错误泰坦：护甲 4 · 分裂 · 尖刺 2）在 Lv20 无技能时必然被击退**——26.6 击才能打死它，而尖刺把"可承受回合"从 30 压到 21。这是**设计意图**（头目需要准备：4 本普通书就降到 17%，稀有及以上为 0%），且被击退零惩罚、只是白打一场。
- 小怪与精英在所有配置下都是 **0%**：安全边际 4.0× / 2.8× 生效，"风险只发生在头目与极端长回合怪上"。
- 技能档的加速（表 B，实测）：小怪 5.1 → 3.3 击（快 **35%**）、精英 10.6 → 6.0（快 **43%**）、头目 26.6 → 15.4（快 **42%**）——比 `10` 文档预期的更强，原因与偏差一并记在 `10` 第十节。

## 八、数据与接口

**存档新增（仍为 `v: 1`，可选、缺省补默认）**
- `playerHp`：缺省 = `maxHp`（旧档读入即满血）；被击退时立即回满，所以 0 不会写进存档。
- `playerGuard`：`'half' | 'immune' | null` —— 护盾标签留下的"下一次反击"减伤（周期内没被反击就留到下次）。
- `knockbackAt`：被击退的时间戳（面板据此播一次性演出）。
- `enemy` 对象追加状态键（照 `08:64` 的口径，机制状态进 `enemy`，跨会话不丢）：`enraged: boolean`（狂暴已触发）、`reShieldIn: N`（护盾再生的回合计数）。

**`plugins/nibble/hooks/nibble.js`**
- 新增导出：`playerMaxHp(lv)`、`playerCounter(lv, tier, rarity)`、`playerHpOf(s)`、`COUNTER_R`。
- 新增内部函数：`hurtPlayer()`（扣血 → 归零走被击退流程）、`enemyReaction()`（尖刺 → 反击 → 反震/血偿）。
- `attack()`：攻击结算后接"敌方反应"；**击败成功不反击**；分裂（未击败）仍会反击；被击退走独立返回路径（`logKind = 'knockback'`）。
- `hpBar(s, n, 'player')` 支持玩家血量；`statusLine()` 的心形条、`card()` / `panel()` 的数值区都改为玩家 HP（敌人血量仍在卡片/面板里显示）。
- 玩家 HP **只在攻击与反击时变化**，不加定时器（与"提问即攻击"一致）。

**`vscode-extension/extension.js`**
- `buildState()` 加 `playerHp` / `playerMaxHp` 并**并入 `key`**（否则血条不刷新）。
- 状态栏心形条改用玩家 HP；tooltip 保留敌方 HP 与连击。
- 新增消息 `type: 'knockback'`（被击退演出）。

**日志变化**
- 反击行：`〈怪名〉反击！Nibble -N HP（HP 42/78）`
- 被击退行：见第五节

## 十、兼容、迁移与维护

- 存档仍 `v: 1`；旧档缺 `playerHp` → 满血；敌方 mech 新键由防御式解析接受（未知键忽略、数值夹取范围）。
- 旧档战斗进度不受影响；首次读档不会立即被击退（玩家以满血进入）。
- 维护：改 HP 或反击公式 → 同步常量 + 本文档 + 重跑 `npm run balance:sim`，并重算第七节验收基准表。
