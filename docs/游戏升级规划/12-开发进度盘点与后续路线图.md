## 四、三笔硬债（必须先还）

### 债一：地基缺失（阶段 0 被整体跳过）

`02` 里画的那套架构，代码里一条都没落地：

| `02` 规划 | 代码实况 | 影响 |
|---|---|---|
| `save.json` 带 `schemaVersion` + `migrations/` | 存档是 `v: 1` 扁平结构，靠 `parseArsenal` / `ensureSkills` 之类的**脏数据静默清理**兜底 | 加进化字段时无法安全迁移，旧档只能"读时补默认值"，越加越脆 |
| `rules/*.json` 配置化 | 内容是 `lib/enemies.js`、`lib/weapons.js`、`lib/skills.js` 里的 **JS 数组字面量** | 加一只怪要改代码 + 发版，`03` 承诺的"加一条 JSON 就热更"完全做不到 |
| 事件总线 `GameEvent` | hook 直接 `require('nibble')` 调 `attack()` | 后面接 `diagnostics.change` / `test.result` 时无处安放 |
| 游戏核心为纯逻辑、可单测 | 逻辑与渲染/IO（`fs`、`os`、ANSI）混在同一个 1100+ 行文件里 | 单测只能测边角，平衡靠 `balance-sim` 外部跑 |

**代价已经出现**：同一套数值公式被**写了三遍**——
- `vscode-extension/lib/nibble.js`（51 个函数）
- `nibble-desktop/lib/nibble.js`（41 个函数，缺技能书）
- `site/site.js`（1104 行附近又重写了一遍 `xpNeed` / `playerAtk` / `rollRarity` / `attack` / `streak`）

`xpNeed = 20 + (lv-1)×15` 和 `playerAtk = 4 + 1.2lv` 在三个文件里各有一份。**改一次数值要改三处，漏一处就是桌面版和官网与扩展不一致。**

### 债二：核心差异化缺席

`00` 里写得很清楚：🥇 行为画像进化是"第一差异化卖点，别人没有"。`01` 给它好玩度 ★★★★★。
**但代码里 0 行。** 现在所有玩家的小狗从 1 级到 60 级长得一模一样，跟第 0 天没区别。

这是整个升级方案里"最值钱、也最容易做砸"的一块：值钱在于它把"玩游戏"变成"养自己"；做砸在于它天然想读代码内容（多写测试？多 debug？），而这条红线不能碰。

### 债三：留存引擎缺席

`G5` 目标写着"7 日留存 +30%"，支撑物是成就 / 日常 / 赛季。现在**三个都没有**。
玩家当前的长期目标只有"把 80 把武器 / 50 本书 / 40 只怪收满"——收满即毕业，毕业即卸载。这是典型的"内容消费型留存"，只能靠不断加内容续命，而加内容的成本现在又很高（见债一）。

## 五、后续开发计划（v0.7 → v1.0）

排期原则：**先还地基，再做差异化，最后补留存**。地基不还就做进化，等于在沙子上盖楼。

```
v0.7 地基补课 ──┬─→ v0.8 行为画像进化（★核心）──┬─→ v0.9 留存引擎 ──→ v1.0 赛季与多端统一
                └─→ v0.7.x 阶段 1 补完（可选并行）  └─→ v0.8.x 互动（情感绑定，可并行）
```

### 阶段 A · v0.7 地基补课（不可跳过）

**目标**：把 `02` 的架构一次性补齐，此后所有内容都不再改核心代码。

任务清单：
1. **抽 core 包**：新建 `packages/nibble-core/`，把战斗 / 掉落 / 连击 / 技能判定 / 进化（未来）抽成纯函数模块，零 `fs` / 零 `os` / 零 ANSI。三端改为依赖它（先扩展，再桌面，最后官网）。
2. **存档加 `schemaVersion`**：从 `v:1` 升到 `schemaVersion: 2`，写 `migrations/v1_to_v2.js`，用现有 `save.json` 样本做回归（旧档不丢武器/技能书/图鉴/连击）。
3. **内容转 `rules/*.json`**：`enemies.json`(40) / `weapons.json`(80) / `skills.json`(50) / 后面要加的 `species.json` / `achievements.json`。**像素网格可以先留在 `*-pixels.js`**（体积大、不常改），只把**数值与文案**搬进 JSON。
4. **事件总线**：`GameEvent` 统一模型 + `emit(type, payload)`，hook 从"直接调 attack"改为"发事件"。为后面 L1 信号预留接口但不启用。
5. **建 golden test**：用现有 `balance-sim` 输出做基线快照，重构后逐格对比，确保"行为不变"。

**验收**：① 旧 `save.json` 升级后 0 字段丢失；② 新增一只怪只需加 JSON 条目、不发版即可出现在战斗里；③ `npm test` 覆盖 core 包 ≥ 现有 6 项；④ 三端数值公式只有一份实现。

**风险**：这是纯重构，玩家无感，容易半途而废 → 建议限时两周、只做 1~4，golden test 可以后补。

### 阶段 B · v0.8 行为画像进化（差异化核心）

**目标**：不同编码习惯的玩家长出不同的小狗形态，且**不读一个字节代码内容**。

**关键设计——只用 L0 节拍，不碰 L1**：

现有节拍已经足够推出三类画像，全部来自"时间戳"，不涉及任何内容：

| 分支 | 节拍指纹（纯 L0） | 判定信号 |
|---|---|---|
| 守护 Guardian（光/高 HP） | 反复验证型 | 保存次数 / 提问次数 **比值高**；会话内动作细密均匀 |
| 猎手 Hunter（暗/高暴击） | 高频试错型 | **提问间隔中位数短**（连续追问）；短间隔连发次数多 |
| 智慧 Sage（水/高幸运） | 深读写型 | **单段静默时长长**；提问频次低但连续会话长 |
| 均衡 Balance | 三者接近 | 三系权重差值 < 0.1 |

实现要点：
- `save.json` 加 `behaviorProfile: { guardian, hunter, sage }`（各 0~1，和为 1）
- 每次 `attack()` 用**指数滑动平均**（α≈0.05）更新，避免单次熬夜把分支带偏
- 判定：某系 ≥0.40 **且**领先次高 ≥0.10 → 成体；等级 ≥20 且该系累计领先 → 完全体
- 平滑期保护：**≥100 次动作才允许首次进化**，避免新手第一天就锁死分支
- 可逆：提供"洗点"（一次性，或每赛季一次），避免玩家后悔

内容与表现：
- `rules/species.json`：3 分支 × 3 阶 + 均衡 1 条 = 10 形态（沿用 `03` 的表）
- 像素走现有管线：`png2grid.mjs` 出 24×24 网格，配色改 `tintGrid` 的色板
- 进化演出：复用 `scene.js` 的相位管线，播一次全屏光效 + 形态切换（不用新写一套动画系统）
- 新增「🐾 物种图鉴」第 4 个图鉴页（与武器/怪物/技能书并列），记录已见形态

**验收**：① 用三套模拟节拍跑 `balance-sim` 式的画像回归，三种玩家分别长出三种形态，错误率 <5%；② 代码里搜不到任何读文件内容 / 路径 / prompt 的调用；③ 进化后主属性有明显差异（守护 HP +20%、猎手暴击 +10%、智慧幸运 +15% 之类）；④ 旧档玩家首次进化不早于第 100 次动作。

**风险**：① 画像太敏感 → 玩家"被贴标签"反感 → 用"你最近偏向 XX"软表述，不叫"你是什么型"；② 分支不可达 → 必须做四分支可达性模拟；③ 与技能书/武器的数值叠加失衡 → 进化加成走乘法前的基础属性，不碰倍率。

### 阶段 C · v0.9 留存引擎

**目标**：给"明天为什么还要打开"一个答案。

1. **积分经济**：击败 / 连击达标 / 日常完成 → 积分（`coins`）。**不做付费、不做内购**（`00` Won't 清单已定）。
2. **成就**（30 条起步，`rules/achievements.json`）：连续活跃 7/30 天、单局 50 连、收满一个稀有度、首次进化、击杀某只头目 10 次…… 奖励皮肤 / 光环 / 称号。
3. **日常**（3 条/天，滚动刷新）：基于**已有的 L0 节拍**生成，例如"今天提问 20 次""今天打满 30 连""今天在 21 点后还在写代码"。**不要设计需要 L1 的日常**（如"修复 5 个错误"），否则逼用户开权限。
4. **面板**：底部面板加「📋 任务」tab（与现有三个图鉴 tab 同级），不做新窗口。

**验收**：① 新玩家 7 日有明确可追目标；② 30 条成就里至少 10 条可在第一周内达成；③ 积分有明确出口（装饰 / 洗点 / 皮肤），不产生通胀；④ 全部判定走 L0。

### 阶段 D · v0.10 互动与情感（可与 C 并行）

**目标**：从"工具"变"伙伴"。

1. **抚摸**：面板里点小生物 → 摇尾巴 / 转圈 + 好感度 `affinity` +1（日上限 5）
2. **喂食**：积分换食物，喂食后 30 分钟内攻击 +5%（**轻量 buff，不做复杂养成**）
3. **小窝**：~~积分换背景 / 家具，纯表现，2~3 套起步~~ **已提前落地**——v0.6.6 的小屋系统走的是「击败掉落收集」而非积分兑换，规模也远超原设想（60 件物品 + 等距渲染）；积分出口可改为屋内互动（见 CHANGELOG `0.6.6`）
4. **档案页**：`rules/stories.json` 解锁式短文案（`03` 第五节那四条已经写好，直接用）

**验收**：互动不影响战斗平衡（buff 上限 +5%）；所有互动都在面板内主动触发，不弹窗。

### 阶段 E · v1.0 赛季与多端统一

## 九、一页纸结论

1. **玩法不缺，缺的是"地基"和"理由"。** 战斗/收集/表现已经做到中上水准（80 武器 + 50 技能 + 40 怪 + 三套场景 + 相位演出），但那是"内容消费型"的爽，收满就结束。
2. **v0.7 必须先还地基**：core 包 + `schemaVersion` + `rules/*.json` + 事件总线。现在同一个公式写了三遍、加一条内容要改代码发版，这已经是可见成本，不是理论风险。
3. **v0.8 是真正的分水岭**：行为画像进化能在**零隐私代价**（纯时间戳节拍）下做出"你的狗长成你的样子"，这是市面上没人做的东西，也是 `00` 自己排的第一卖点。
4. **v0.9 补留存**，但日常必须建在 L0 节拍上，不能设计"修 5 个 bug"这种逼人开权限的任务。
5. **桌面版的键盘监听是当前最大隐私敏感点**，`05` 里还没有这一条，建议立规矩、补文档、加开关。
