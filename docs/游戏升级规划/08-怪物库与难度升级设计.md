# 08 · 怪物库与难度升级设计

**定位**：把战斗的"对手"从 3 只硬编码杂兵，升级为一套**数据驱动的 40 只怪物图鉴**——命名与故事全部取材于"编程世界的 Bug"，并靠数值分级把战斗难度拉起来。
**状态**：已落地（40 只数据 + 遭遇/击败双状态图鉴 + tier 数值分级与精英机制 + 面板怪物库标签页 + 40 张独立像素素材）。
**依赖**：`07-武器库收集系统设计.md`（收集系统的范式来源），`03-内容规划.md` 第二节（敌人草案）。

## 一、设计决策

| 决策 | 结论 | 理由 |
|---|---|---|
| 难度提升走哪一档？ | **A+ 档：数值分级 + 风险层（零惩罚）** | 引入玩家 HP 与怪物反击，但**归零零惩罚**（换新怪 + 断连击，见 `11-玩家血量与怪物反击设计.md`），不改变"提问即攻击"的单向节拍；仍靠 tier / 稀有度 / 等级三重缩放 + 精英机制变难 |
| 怪物库收录口径？ | **遭遇 + 击败双状态** | 首次 `seen` 即入库（灰调可看故事），击败后 `defeated` 点亮为彩图并累计次数 |
| 命名与故事来源？ | **全部取材"编程 Bug"** | 与 `03` 的"代码世界具象化"世界观、武器库的命名风格一致 |
| 规模？ | **40 只**（小怪 20 / 精英 14 / 头目 6） | 数量够撑收集欲，命名与故事仍有辨识度 |
| 每个怪物素材？ | **40 张独立 24×24 像素画** | 与武器库同管线；复用同一套切片/裁剪/调色板工具 |
| 数据放哪？ | `plugins/nibble/hooks/enemies.js` + `enemies-stories.js` + `enemies-pixels.js` | 与 `weapons*.js` 完全同构，零依赖、随 `sync-lib` 进扩展 |

## 二、难度模型（A+ 档）

### 2.1 数值公式

```js
baseHp(lv)         = round(21 + lv * 5.95)      // 与「等级攻击 × 普通武器战力(+8%)」配平（v0.4.0 战力系统上线后重算）
maxHp(lv, tier, r) = round(baseHp(lv) * TIER_MUL[tier] * RARITY_MUL[r] * (0.9 + Math.random() * 0.2))
```

| 维度 | 取值 |
|---|---|
| `TIER_MUL` | 小怪 `1.0` · 精英 `2.0` · 头目 `3.6` |
| `RARITY_MUL` | 普通 `1.0` · 稀有 `1.15` · 史诗 `1.35` · 传说 `1.6` |
| 玩家攻击 | **`playerAtk(lv) = round(4 + lv * 1.2)` ×（1 + 武器战力%）**（v0.4.0：等级成长由 `4 + 2lv` 压低，缺口交给武器战力；攻击值计算保留小数） |
| 伤害 | `round(atk * (0.9 + rand * 0.2))`（v0.4.0 由固定 `+rand(5)-2` 改为比例 ±10%，否则低等级抖动会淹没武器差距） |
| 击败经验 | `6 + round(maxHp * 0.6)`（原 `8 + maxHp`；怪物变硬后避免升级过快而反向抵消难度） |
| 稀有度抽取 | 不变：`rollRarity(lv)`（70/20/8/2 基准，随等级轻微上浮） |

> 难度体感 = "打得久 + 有机制 + 武器够不够好"：普通小怪约 5 次提问，精英约 11 次，头目 25~30 次（头目的"久"主要来自 `armor` 与 `split`）。
> ⚠️ 改 `playerAtk` / `WEAPON_POWER`（见 `07` 战力系统）时，`baseHp` 必须一起用 `tools/balance-sim.js` 重算，否则"武器有作用"会退化成"整体变简单 / 变难"。

### 2.2 出现权重（按等级解锁）

```js
tierWeight(lv):
  common : 100 - min(40, lv * 2)                // 全程，但占比随等级下降
  elite  : lv < 6  ? 0 : min(45, (lv - 4) * 4)  // 首只精英解锁于 Lv6
  boss   : lv < 15 ? 0 : min(12, lv - 13)       // 首只头目解锁于 Lv15
```

按权重抽 tier → 在该 tier 内抽 `minLv <= lv` 的怪物（池子为空则回落到小怪）→ 再 `rollRarity` 决定稀有度与数值。

### 2.3 精英机制（`mech`）

| 机制 | 键 | 结算效果 |
|---|---|---|
| 护甲 | `armor: N` | 每次受击伤害 `-N`，最低仍造成 1 |
| 闪避 | `dodge: p` | 概率 `p` 完全闪避（伤害 0） |
| 自愈 | `regen: N` | 玩家攻击结算后（未死）回复 `N` HP，不超过 `maxHp` |
| 护盾 | `shield: N` | 开场 N 层护盾：受击伤害减半，消耗一层 |
| 分裂 | `split: true` | 首次 HP 归零时分裂为 2 只同 id 的 50% HP 个体（整个战斗只触发一次） |
| 尖刺 | `thorns: N` | 每次受击**反弹 N 点**给玩家（A+ 档新增，见 `11`） |
| 狂暴 | `enrage: true` | 自身 HP < 30% 时，**反击 ×1.5**（触发一次后持久） |
| 护盾再生 | `reShield: N` | 护盾被击穿后，**每 N 回合恢复 1 层** |

> 所有机制状态写入存档的 `enemy` 对象（`shieldLeft` / `splitDone` / `enraged` / `reShieldIn`），跨会话不丢。
> **分配口径（A+ 档）**：尖刺/狂暴/护盾再生**只给精英与头目**，小怪保持上表前 5 种之内；每个精英/头目最多 1 个新增机制、机制键总数 ≤3（强度预算）。分配明细见 `11` 第六节。
> ⚠️ **护盾再生只给"本来就有护盾"的怪**（`mech.shield > 0`）：否则等于凭空每 N 回合造一层盾，会把头目时长拉长 60%（实测：段错误泰坦 26.6 → 42.7 击）。恢复上限 = 开场层数。
> ✅ 三种新机制已随风险层（`11`）落地并生效。

### 3.4 故事文案（`enemies-stories.js` 全量）

> 每只 ≤100 字，围绕该 Bug 的经典坑与情绪展开；改文案只动 `enemies-stories.js`。

**小怪**

- `null_pointer`：「它没有实体，只有一个指向虚无的引用。你每次都以为判过空了，它总能在线上另辟蹊径地出现——`Cannot read property of undefined`，是它留下的脚印。」
- `infinite_loop`：「`while (true)` 是它的墓志铭。它不停绕圈，直到风扇开始尖叫、屏幕开始变白。能杀死它的咒语只有一句：`break`。」
- `off_by_one`：「它从不犯大错，只是永远差一点点。数组最后一个元素、循环的最后一次、分页的最后一页——都是它的藏身处。下标从 0 开始，它笑了。」
- `type_coercion`：「`'1' + 1` 变成 `'11'`，`'1' - 1` 变成 `0`。它靠这套把戏骗过了所有不看类型的人，唯一识破它的是终于打开的 lint 规则。」
- `undefined_var`：「它不是 `null`，不是 `0`，也不是空字符串。它是"什么都没有"，却偏偏存在。它连自己是不是函数都不确定。」
- `index_bounds`：「数组只有十格，它偏要敲第十一格的门。没人在家，于是整段程序原地倒下。它飘在边界之外冷笑：反正你也不会写边界测试。」
- `mojibake`：「UTF-8 出门，GBK 回家，从此面目全非。『你好』变成了『浣犲ソ』，它蹲在乱码里，嘲笑每一个忘了声明 charset 的人。」
- `uncaught_exception`：「抛出去就没人接，一路炸穿整个调用栈。它在最外层炸出最后一声巨响，留下一行堆栈，扬长而去。」
- `float_drift`：「`0.1 + 0.2 = 0.30000000000000004`。它只有小数点后十七位的执念，却让所有 `===` 当场翻车。财务同事至今不肯原谅它。」
- `shadow_var`：「外层有个 `name`，内层也有个 `name`。它站在内层，把外层的名字一口吞掉——你以为改的是全局，其实改的是它。」
- `callback_hell`：「函数套函数，一层又一层，缩进成金字塔，最深处的错误传不上来。它蹲在第七层里等人来找，没有人来。」
- `copy_paste`：「Ctrl+C、Ctrl+V 是它的呼吸。同一个 bug 在十二个文件里同时出现，你修了十一个，第十二个上线了。」
- `magic_number`：「它叫 `86400`，没人知道那是"一天的秒数"——包括三天后的作者本人。它躲在代码里，等着有人把它改成 `3600`。」
- `todo_zombie`：「『暂时这么写，下周重构』。它已经这样躺了三年，注释都褪色了，代码还活得好好的。它是最长寿的临时方案。」
- `hardcode_golem`：「地址写死、密钥写死、路径写死。它坚不可摧——直到换了一台机器、换了一个环境，当场碎成一地。」
- `global_pollution`：「它把名字贴在全局对象上，谁都能改。同事改一个变量，你的模块突然失灵——你们互相都在怪对方。」
- `typo_imp`：「`lenght`、`recieve`、`adress`。编译器不会报错，因为没人规定它该叫什么。它安静地住了三个月，直到有人真的调用了它。」
- `asi_ambusher`：「它躲在换行符后面。你以为那行写完了，JS 也以为——于是 `return` 变成 `return;`，返回值无声消失，你对着断点发呆。」
- `timezone_shift`：「本地跑得好好的，一上服务器就早八小时。它为 UTC 和东八区的时差而战，专挑跨零点的时候发难。」
- `bom_worm`：「它只有三个看不见的字节，躲在文件最前面。解析器见了它当场翻脸，而你瞪着两份一模一样的文件，看不出任何区别。」

**精英**

- `memory_leak`：「它只吃不吐。每分钟涨一点内存，八小时后进程被 OOM 一拳打死。你盯着监控曲线，它在你没清的监听器里打了个饱嗝。」
- `race_condition`：「两个线程同时进门，谁先谁后全看运气。它只在发版那天、只在周五 17:59 出现，复现率 0.03%。关掉日志它就消失，打开日志它就不来。」
- `deadlock_spider`：「A 等 B，B 等 A，两个线程手牵手，谁都不肯先松手。它把出入口全用蛛丝封死，整个服务僵在原地，日志停在最后一行。」
- `stack_overflow`：「函数调用自己、再调用自己，没有终点。调用栈一层层堆到天上，最后『啪』地一声——带着整条栈一起坠落。」
- `n_plus_one`：「它把你的 1 次查询偷偷变成 1+N 次。列表二十条，数据库被敲二十一次。它躲在 ORM 的温柔乡里，越懒越强。」
- `phantom_dependency`：「依赖清单里没有它，`node_modules` 里全是它。它靠别人捎带活到今天，等谁升级一次依赖，整条构建链当场散架。」
- `flaky_test`：「昨天绿的，今天红了，重跑一次又绿了。它一不高兴就红给你看，逼得全组改用 skip。它是流水线上最会撒娇的怪物。」
- `circular_dependency`：「A 引了 B，B 又引了 A，咬住自己的尾巴。模块加载到一半就成了 `undefined`，它自己不觉得奇怪。」
- `cache_invalidation`：「改了数据界面不变，刷新一下才是对的。用户骂你，你骂缓存。它在中间层笑得很大声：谁让你不设过期时间。」
- `dangling_pointer`：「对象早被释放了，引用还留着。它指向一块已经不属于你的内存，用最随机的姿势崩给你看——有时候是崩溃，有时候什么也不发生，那更吓人。」
- `handle_leak`：「文件开着不关、连接用完不还。它一次只吸一点点，直到『打开的文件过多』拍在脸上，服务再也开不了新门。」
- `encoding_nightmare`：「一半 UTF-8，一半 GBK，中间还有人用 ISO-8859-1 转了一手。它的中文一半是问号，另一半是外星文字。」
- `clock_drift`：「两台服务器差了三秒。定时任务早跑一次、晚跑一次，订单扣了两次款。它飘在时间同步的空隙里，安静地制造事故。」
- `silent_failure`：「`catch (e) {}`——它把异常吃干抹净，一声不响。数据没保存，接口返回 200，日志干干净净。它是最擅长伪装的怪物。」

**头目**

- `segfault_titan`：「它一拳打穿整个进程：`Segmentation fault (core dumped)`。不给你堆栈、不给你机会，只留一个 core 文件。所有底层程序员的噩梦，此刻站在这里。」
- `entropy_virus`：「它不修改代码，只是让代码慢慢变乱：命名不一致、格式到处跑、没人再看得懂。它每周分裂一次，规则是——只要没人整理，它就更强。」
- `legacy_colossus`：「三任作者、十五年历史、零测试。注释写着『不要动这里』，动过的人都不在了。它站在仓库中央，挡住整条重构的路。」
- `cascade_avalanche`：「一个下游超时，上游重试三次，再上游再翻三倍。三分钟后整个集群雪崩。它不是一只怪物，它是你架构图上所有箭头的合体。」
- `bit_rot`：「磁盘上的字节在静静腐烂，一年坏一个 bit。备份能恢复数据，却恢复不了它坏掉的那一瞬间。它比代码更古老，也更有耐心。」
- `debt_singularity`：「利息一直在滚。快速上线、临时绕过、下不为例，一圈圈绕成了吞掉整支团队的奇点。它集齐了所有 bug 的形态——因为所有 bug 都是它的碎片。」

## 四、数据与接口

### 4.1 存档新增字段（v1 兼容，旧档自动补默认值）

```jsonc
"bestiary": {
  "seen":     { "null_pointer": { "first": 1735603200000, "count": 7 } },
  "defeated": { "null_pointer": 5 }
},
"enemy": { "type": "race_condition", "rarity": "epic", "hp": 42, "maxHp": 90, "shieldLeft": 2, "splitDone": false }
```

- `seen`：首次遭遇时间戳 + 遭遇次数（**遭遇即入库**）。
- `defeated`：击败次数（>0 才算"已击败"，图鉴点亮）。
- 读档时按 `ENEMY_INDEX` 白名单过滤未知 id（向前兼容加/删怪物，与 `parseArsenal` 同策略）。

### 4.2 模块职责

| 模块 | 内容 |
|---|---|

## 六、素材管线（40 张独立像素画）

1. **源图**：`legacy-mods/assets/monsters/sheets/`——AI 生成原创像素画，绿幕底，按 4×2（8 只）/ 2×2（4 只）/ 3×2（6 只）排列，每张一格一只怪。**文件名固定为** `01-common-1.png` / `02-common-2.png` / `03-common-3.png` / `04-elite-1.png` / `05-elite-2.png` / `06-boss-1.png`，与 `SHEETS[].file` 一一对应（不依赖目录排序）。
2. **提示词要求**（`07` 踩坑）：`flat chunky pixel art, hard edges, NO glow / particles / anti-aliasing`；同一张排列图内风格必须统一（同色系、同比例）。⚠️ 头目若提示词偏"dark palette"，降采样后会在深色面板上糊成一团——已改为 **bright saturated colors + high contrast**。
3. **构建**：`node tools/monsters-sprites.mjs`（= `npm run sprites:monsters`）→ 切片 → 抹水印/边框 → 绿幕清理 → 密度裁剪 → 24×24 调色板网格 → `plugins/nibble/hooks/enemies-pixels.js`，同时输出人工核验拼图 `legacy-mods/tools/preview/monsters/contact-{common,elite,boss}.png`。
4. **切片存档**：`legacy-mods/assets/monsters/cells/`（可再生中间产物，见 `.gitignore` 口径）。
5. ⚠️ `image_gen` 的 `output_dir` 相对**工作区根目录**，生成后需挪入仓库素材目录；且**不要并行生成多张同格数的图**——文件名里的时间戳可能相同导致互相覆盖（本项目已踩过一次：两张 8 格图撞名，丢掉一批素材）。
6. ⚠️ 排列图内格子顺序必须与 `SHEETS[].ids` 严格一致，否则整批错位（构建脚本只会校验格数，错序必须靠 contact 拼图人工核验）。
7. 构建后需 `npm run sync` 让扩展侧 `lib/` 拿到新素材；本地核验用 `npm run preview:html` + `npm run preview`。

## 七、兼容、迁移与维护

### 7.1 兼容

- 存档仍是 `v: 1`，新增字段全部可选、缺省补默认。
- 旧档里的 `enemy.type`（`bat` / `slime` / `mimic`）不在新白名单中 → 读档时被丢弃并**重新抽取一只新怪**，战斗进度不丢（等级/经验/战绩/武器库原样保留）。
- `pixels.js` 中的旧三张敌人网格不再被引用（主角 `player` 仍在此文件），保留不删以免破坏历史引用。
- A+ 档新增的 mech 键（`thorns` / `enrage` / `reShield`）按缺省处理：旧档读入时缺省无狂暴、无再生层；未知/多余键静默忽略。优先级为 **旧档直接用**，不做迁移。

### 7.2 构建同步

- `tools/sync-lib.js` 的 `FILES` 加入 `enemies.js`、`enemies-stories.js`、`enemies-pixels.js`。
- `reset()` 一并清空怪物库（`bestiary`）。
- 版本号：`0.2.1` → `0.3.0`（新增功能，非破坏性）。

### 7.3 加一只怪物（标准流程）

1. 在 `hooks/enemies.js` 的 `ENEMIES` 追加 `{ id, name, tier, minLv, mech }`（id 唯一）。
2. 在 `hooks/enemies-stories.js` 追加同 id 的故事（≤100 字，围绕一个真实 Bug）。
3. 在 `legacy-mods/assets/monsters/sheets/` 补素材，改 `tools/monsters-sprites.mjs` 的 `SHEETS` 清单，重跑脚本。
4. `npm run sync` 后在三种载体下验证图鉴与战斗。
5. 无需改动任何战斗核心代码（数据驱动）；旧档不受影响（未知 id 静默丢弃）。

### 7.4 数值调整

- 全局强度 → 调 `TIER_MUL` / `RARITY_MUL` / `baseHp` 系数；
- 单只强度 → 调该条的 `mech`（护甲/自愈/护盾/闪避/分裂/尖刺/狂暴/护盾再生）；
- 出现节奏 → 调 `tierWeight(lv)` 的三条曲线。
- 风险层数值（玩家 HP / 反击百分比 / 击退率）→ 见 `11`，改完必须重跑 `npm run balance:sim` 并重算其验收基准表。
- 重要调整走 `06` 的回归与平衡测试，并回写本节。
