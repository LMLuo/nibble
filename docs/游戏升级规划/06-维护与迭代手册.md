# 06 · 维护与迭代手册

**定位**：游戏上线升级版本后的长期运维规范。覆盖版本规范、数据迁移、内容热更、反馈闭环、回归测试、路线图评审。

---

## 一、版本规范（SemVer）

| 变更类型 | 版本 bump | 示例 |
|---|---|---|
| 内容热更（加物种/技能/成就，无核心改动） | patch | v0.4.1 |
| 机制/玩法新增（阶段 1~4） | minor | v0.5.0 |
| 不兼容存档/架构大改 | major | v1.0.0 |

- 沿用现有发布链路：`git tag v*` → CI 校验 → `sync-lib` → vsce 打包 → Open VSX 发布（`PUBLISHING.md`）。
- 阶段 0~4 为 `0.x` 快速迭代；阶段 5 稳定后进入 `1.0`。

## 二、数据迁移策略

- `save.json` 带 `schemaVersion`（`02` 第三节）。读取时若低于当前版本，按 `migrations/` 顺序升级。
- 迁移原则：**缺字段补默认值、不删已有进度、失败回退安全默认值并提示**。
- 大版本（major）迁移前，在 CI 中加"旧档回归"用例，用历史样本档验证不丢数据。

## 三、内容热更流程（核心优势）

阶段 0 完成后，内容扩展无需发版：
1. 在 `rules/*.json` 增加条目（`03` 第七节）。
2. 扩展读取最新 `rules/` 即生效（可考虑"规则版本号 + 静默拉取"或随扩展发版）。
3. 重大数值调整走本手册第五节平衡测试。
> 这让"运营周更物种/赛季"成为可能，是留存的关键能力。

## 四、反馈闭环

- 交互面板内置"反馈/建议"入口（轻量，本地或 opt-in 上报聚合数据）。
- 定期（每阶段结束）汇总反馈，回写 `01`（机制调整）与 `05`（风险）。
- 隐私：反馈默认不上报内容；如需诊断信息，明确告知且仅聚合。

## 五、回归与平衡测试

- 沿用 `npm test`（扩展自检）+ 新增游戏核心单测（战斗/进化/迁移）。
- 每个阶段退出前跑全量测试；新增机制须带单测。
- 平衡测试：用模拟行为画像验证各进化分支可达、数值不崩（`05` R6）。

## 六、路线图评审节奏

- **每季度**回看 `04` 里程碑，结合实际数据与 `05` 风险，调整 `00` 的 MoSCoW 优先级。
- **每个阶段结束**做一次小型复盘：写了什么、踩了什么坑、下阶段改什么，记录到本册"复盘记录"。

## 七、文档同步规范

- 机制变更 → 更新 `01` + `03` + `04`。
- 隐私/权限变更 → 更新 `02` 第八节 + `05` R1。
- 新增风险 → `05`。
- 发版 → `06` 复盘 + 回写受影响章节。
- `README.md` 目录结构稳定，文件名序号不随版本变，便于长期引用。
