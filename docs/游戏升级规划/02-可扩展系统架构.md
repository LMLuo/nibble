# 02 · 可扩展系统架构

**定位**：把 `01` 的玩法落到工程上。定义事件层、数据模型、规则数据化、渲染层、触发层、扩展点与**隐私分级**。
**约束回顾**：hook 跑 Windows Git Bash + Node16（轻量、守语法）；扩展（IDE 侧）有完整 API，可做重 UI 与"只读聚合信号"的游戏化。

---

## 一、总体架构（分层）

```
┌─────────────────────────────────────────────┐
│  表现层（渲染）                               │
│  状态栏(轻) → 战场面板 → 交互面板(主动开) → 大图 │
├─────────────────────────────────────────────┤
│  触发层（事件来源）                            │
│  hook / onSave / manual / extension-events(opt-in)│
├─────────────────────────────────────────────┤
│  事件/信号总线（统一事件 → 游戏状态机）          │
├─────────────────────────────────────────────┤
│  游戏核心（状态机 + 规则引擎，纯逻辑、可测）      │
│  战斗 / 养成 / 进化 / 技能 / 任务 / 收集        │
├─────────────────────────────────────────────┤
│  数据层                                       │
│  save.json（模块化 + schemaVersion + 迁移）     │
│  rules/（物种/技能/敌人/成就 配置，可热更）      │
└─────────────────────────────────────────────┘
```

设计要点：**游戏核心为纯逻辑模块**，不依赖 IDE；hook 与扩展都只是"事件源"和"渲染端"。这样核心可在 Node 单测，跨 IDE 复用。

---

## 二、事件 / 信号层

统一事件总线，所有来源归一为 `GameEvent`：

| 事件类型 | 来源 | 权限 | 示例 |
|---|---|---|---|
| `prompt.submit` | hook（已有） | L0 | 普通攻击 |
| `file.save` | hook/onSave（已有） | L0 | 攻击/蓄力 |
| `session.start/end` | hook（已有） | L0 | 出战/收工 |
| `focus.idle` | 扩展计时 | L0 | 睡觉/饥饿 |
| `focus.concentrate` | 扩展计时 | L0 | 专注态 |
| `diagnostics.change` | 扩展（opt-in） | L1 | 刷/击败怪物（只带计数） |
| `test.result` | 扩展（opt-in） | L1 | 暴击（只带通过/失败布尔） |
| `git.commit/push` | 扩展（opt-in） | L1 | 大招/Boss |
| `file.create/delete` | 扩展（opt-in） | L1 | 探索/环境变化（只带计数） |

> **L1 事件严格只传聚合信号**：如 `{type:'diagnostics.change', errors:3, warnings:1}`，**绝不传文件名、错误文本、代码片段**。扩展侧读取后立刻丢弃原始数据，只把计数喂给游戏核心。

## 三、数据模型（save.json 演进）

**现状**：扁平结构（level / xp / score / currentEnemy）。
**目标**：模块化 + 版本号，支持迁移。

```jsonc
{
  "schemaVersion": 3,
  "meta":   { "createdAt": "...", "lastSession": "...", "triggerMode": "hook" },
  "creature": {
    "speciesId": "guardian_2", "level": 12, "xp": 340,
    "stats": { "hp": 80, "atk": 30, "def": 25, "spd": 18, "luck": 12 },
    "affinity": 60, "form": "adult"
  },
  "battle":  { "enemy": {...}, "combo": 0, "energy": 40, "focus": 0.5 },
  "behaviorProfile": { "test": 0.4, "debug": 0.3, "doc": 0.3 }, // 驱动进化
  "collection": { "speciesSeen": ["..."], "monstersCaught": ["..."], "skins": ["..."] },
  "quests":  { "achievements": ["..."], "daily": {...}, "season": {...} },
  "inventory": { "coins": 120, "food": 2, "decor": ["..."] }
}
```

- **迁移**：读取时若 `schemaVersion` 低于当前，按 `migrations/` 顺序升级，缺字段补默认值，**绝不丢已有进度**。

## 四、规则数据化（内容可热更的关键）

核心代码不写死数值，全部读 `rules/` 配置：

| 配置 | 内容 | 维护方 |
|---|---|---|
| `rules/species.json` | 物种演化树、属性、解锁条件 | 策划/开发 |
| `rules/enemies.json` | 怪物属性、出现权重、掉落 | 策划 |
| `rules/skills.json` | 技能效果、触发、组合 | 策划 |
| `rules/achievements.json` | 成就/日常定义 | 策划 |
| `rules/seasons.json` | 赛季主题、限定内容 | 运营 |

> 阶段 0 完成数据化后，**新增一个物种 = 加一条 JSON，无需改核心代码**，对应 `00` 目标 G4。

## 五、渲染层（UI 分配）

| 载体 | 职责 | 交互强度 |
|---|---|---|
| 状态栏 | 等级/HP 小条/连击数（极简） | 只读 |
| 底部战场面板 | 当前战斗 24×24 + 一行日志 | 轻交互（攻击按钮） |
| **交互面板（新增）** | 图鉴/任务/技能/小窝/设置（标签页） | 重交互，用户主动打开 |
| 编辑器标签页大图 | 完整 24×24 欣赏 | 只读 |

- 重交互集中在"交互面板"，避免占用状态栏/底部空间，守住"轻量不打扰"原则。

| 模式 | 说明 | 备注 |
|---|---|---|

## 七、扩展点（社区/未来）

- **皮肤/物种 mod 接口**：定义 `SkinSpec`（像素网格 + 配色），允许社区贡献头像与主题。
- **规则 hook**：预留 `onBattleResolved` 等钩子，供高级用户/插件扩展结算逻辑。
- 所有扩展点默认关闭，不影响隐私基线。

---

## 八、隐私分级（架构级红线）

| 等级 | 能力 | 默认 | 要求 |
|---|---|---|---|
| **L0 零读取** | 仅用动作节拍（提问/保存/计时） | ✅ 开 | 现有承诺，永不读内容 |
| **L1 只读聚合** | 读诊断计数、测试布尔、commit 发生等**数字/布尔** | ❌ 关（opt-in） | 不读内容；UI 明确告知"只读数" |
| **L2 深度** | 未来可能的深度能力 | ❌ 关 | 需用户显式授权 + 独立声明，本版不做 |

> 任何新增机制若在 `01` 中标记 L1/L2，必须在此登记并在 `05` 评估。L1 事件在扩展侧处理后**立即丢弃原始数据**，只保留聚合值写入 `save.json`。

---

## 九、性能与兼容要点

- hook 端逻辑保持轻量（仅 emit 事件 + 落盘），重计算（进化判定、图鉴统计）放游戏核心，必要时由扩展侧触发。
- 守 Node16 语法（Windows Git Bash 环境）；`package.json` 的 `engines.vscode` 用具体版本（避免静默不加载）。
- 沿用既有发布链路（CI tag → vsce → Open VSX），新增模块不引入额外原生依赖。
